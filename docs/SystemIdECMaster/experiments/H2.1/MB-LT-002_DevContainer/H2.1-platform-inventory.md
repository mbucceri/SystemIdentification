## Scope and evidence boundary

H2 requires development-host facts, target-host facts, and derived conclusions
to remain separate. This run was performed as user `vscode` in a Docker-style
Dev Container. `/proc`, `/sys`, the network namespace, cgroups, and available
devices are container-visible views. The workspace is bind-mounted from the
development machine, but that does not make host hardware or host kernel state
observable.

Accordingly, the observations below are labelled **container-visible**. They
must not be treated as direct facts about the underlying development host or
the eventual EtherCAT target. No target-host evidence has been collected or
imported yet.

## Important observations

- The current execution environment is isolated: `/sys` is read-only, the
  network namespace exposes only a virtual `eth0`, and `/proc/interrupts` is
  not useful for identifying physical NIC IRQs.
- The visible CPU and frequency data describe what the container can see, not
  a controlled real-time test environment.
- The 64 KiB memory-locking limit and zero realtime priority limit apply to the
  probe process in this container. They are not target-host limits.
- The absence of optional tools and IgH/EtherLab components in the container
  is expected to be an environment observation, not a platform decision.
- No timing test was run. In particular, this inventory does not verify the
  1 ms cycle or the ±100 µs target, and it does not establish whether
  PREEMPT_RT is required or sufficient.

## Unresolved platform questions

The following require a direct target-host run, normally with the appropriate
read-only visibility:

1. What distribution, kernel configuration, command line, and PREEMPT_RT
   state does the actual target use?
2. What physical CPU topology, frequency policy, hypervisor status, and
   scheduler configuration apply on the target?
3. Which physical NIC vendor/model, PCI address, kernel driver, IRQs, and IRQ
   affinities are available for the EtherCAT link?
4. What are the target process limits for realtime priority and locked memory?
5. Are `cyclictest`, `perf`, `trace-cmd`, `ethtool`, and `lspci` available on
   the target, and what versions are installed?
6. Which IgH/EtherLab userspace library, kernel modules, command-line tools,
   and release/branch are installed or buildable on the target?
7. What target-host timing measurements under representative load are needed
   to address the 1 ms / ±100 µs requirement? This inventory intentionally
   does not answer that question.
